查找

基础知识

基本概念

  • 查找：在数据集合中寻找满足某种条件的数据元素的过程。
  • 查找表：用于查找的数据集合。
  • 关键字：数据元素中唯一表示该元素的某个数据项的值。

常见操作

  • 查找符合条件的数据元素。
  • 插入、删除某个数据元素。

评价指标

  • 查找长度：查找运算中，需要对比关键字的次数。
  • 平均查找长度$(ASL,Average{\ }Search{\ }Length)$：所有查找过程中进行关键字比较次数的平均值，需要考虑查找成功和查找失败两种情况。

基本查找算法

顺序查找

  通常用于线性表，从头到尾依次查找。

  • 查找效率：查找成功时，每个元素成功概率为$\frac{1}{n}$，$ASL=\frac{1+2+…+n}{n}=\frac{n+1}{2}$；查找失败时，每个元素失败概率都是$1$，因此$ASL$为$n+1$。

对有序表的查找优化

  由于有序树中元素按照递增或递减顺序查找，如下所示的查找判定树，一共可能出现$n+1$种查找失败的情况，每种情况概率是$\frac{1}{n+1}$，则查找失败的$ASL=\frac{1+2+…+n+n}{n+1}=\frac{n}{2}+\frac{n}{n+1}$（最后两种情况都需要比对$n$个关键字，因此最后加了两次$n$）。

  • 在判定树中，一个成功结点的查找长度为自身所在层数，失败结点的查找长度为父结点所在层数。

被查找概率不相等

  当各个元素被查找概率不相等时，可以将查找概率大的放在前面，从而缩短查找长度，但是查找失败时仍需遍历整个表。

折半查找

  又称二分查找，只适用于有序的顺序表。

  查找判定树如下所示：

  折半查找判定树的构造：

  • $mid=\lfloor (low+high)/2 \rfloor$，如果有奇数个结点，则左右子树元素个数相等；如果有偶数个结点，则右子树比左子树多一个元素。
  • 折半查找判定树一定是平衡二叉树，并且只有最下面一层是不满的，所以元素为$n$时树高$h=\lceil log_2(n+1) \rceil$。
  • 判定树结点关键字：左$<$中$<$右。
  • $n$个结点的判定树，失败结点有$n+1$个（空链域数量）。
  • 折半查找的时间复杂度为$O(log_2n)$。

分块查找

  1. 先在索引表中确定所属分块，可以顺序查找，也可以折半查找。

    若索引表不包含目标关键字，则折半查找索引表最终会停在$low>high$的位置，此时应该在$low$指向的分块中查找。

  2. 在块内顺序查找。

均匀分块的查找效率

  长度为$n$的查找表被均匀分为$b$块，每块有$s$个元素。

  • 顺序查找：索引查找的平均查找长度为$L1=\frac{1+2+…+b}{b}=\frac{b+1}{2}$，块内查找的平均查找长度为$L_2=\frac{1+2+…+s}{s}=\frac{s+1}{2}$，$ASL=L_1+L2=\frac{b+s+2}{2}$，将$b=\frac{n}{s}$代入可得$ASL=\frac{s^2+2s+n}{2s}$，当$s=\sqrt{n}$时，$ASL{min}=\sqrt{n}+1$。
  • 折半查找：$L_1=\lceil log_2(b+1) \rceil,L_2=\frac{1+2+…+s}{s}=\frac{s+1}{2},ASL=\lceil log_2(b+1) \rceil + \frac{s+1}{2}$。

树在查找中的应用

二叉排序树(BST)

  左子树结点值$<$根结点值$<$右子树结点值。

插入操作

  若原二叉排序树为空，则直接插入结点；否则，若关键字小于根结点值，则插入左子树，若关键字大于根结点值，则插入右子树。

删除操作

  • 如果是叶结点，则直接删除。
  • 如果该结点只存在左子树或右子树，则将其左孩子或者右孩子连在父结点。
  • 如果既有左子树，又有右子树，可以用下面两种方法
    • 选取该结点的直接后继替代这个结点，也就是找到右子树中最左下的结点，详见中序线索二叉树找后继。
    • 选取该结点的直接前驱替代这个结点，也就是找到左子树中最右下的结点，详见中序线索二叉树找前驱。

查找效率

  查找长度不会超过这棵树的高度，时间复杂度同查找长度，树的高度越低，$ASL$越短。将二叉排序树转化为平衡二叉树即可实现这一点。

平衡二叉树(AVL树)

  树上任一结点的左子树和右子树高度之差不超过$1$。平衡因子指的是左子树高$-$右子树高。

插入操作

  只需要调整最小不平衡子树$A$即可恢复平衡，有如下四种情况：

  • $LL$：在$A$的左孩子的左子树中插入导致不平衡。

  右单旋转，让$B$向右上旋转成为根结点，$A$向右下旋转成为$B$的右子树的根结点，而$B$原先的右子树成为$A$的左子树。

  • $RR$：在$A$的右孩子的右子树中插入导致不平衡。

  左单旋转，让$B$向左上旋转成为根结点，$A$向左下旋转成为$B$的左子树的根结点，而$B$原先的左子树成为$A$的右子树。

  • $LR$：在$A$的左孩子的右子树中插入导致不平衡。

  先左后右双旋转，$A$结点的左孩子$B$的右子树根结点$C$左上旋到$B$的位置，然后把$C$结点向右上旋转到$A$的位置。

  • $RL$：在$A$的右孩子的左子树中插入导致不平衡。

  先右后左双旋转，$A$结点的右孩子$B$的左子树根结点$C$右上旋到$B$的位置，然后把$C$结点向左上旋转到$A$的位置。

删除操作

  具体步骤：

  1. 删除结点，同二叉排序树的删除。
  2. 检查是否不平衡。
  3. 确定最小不平衡子树，找到该子树下最高的儿子和孙子结点，根据类型进行调整。
  4. 若不平衡向上传导，则继续调整直至平衡。

红黑树

  平衡二叉树的插入和删除操作很容易破坏“平衡”特性，需要频繁调整树的形态；红黑树的插入和删除很多时候不会破坏，无需频繁调整。红黑树是二叉排序树，除二叉排序树的特性外还具有如下特性：

  1. 每个结点是红色或黑色的。
  2. 根节点是黑色的。
  3. 叶结点（外部结点、$NULL$结点、失败结点）均为黑色。
  4. 不存在两个相邻的红色结点（父子关系）。
  5. 对每个结点，从该节点到任意叶结点的简单路径上，所含黑结点的数目相同。

  根据如上特性，红黑树具有了如下的性质：

  1. 从根节点到叶结点的最长路径不大于最短路径的二倍。
  2. 有$n$个内部节点的红黑树高度$h \leq 2log_2(n+1)$。

插入操作

  1. 通过查找确定插入位置，插入新结点。

    • 若新节点是根结点，则为黑色；否则为红色。

  2. 插入的结点是否满足红黑树定义，满足则结束，否则进行调整。

删除操作

  红黑树的删除操作时间复杂度为$O(log_2(n))$，删除结点的处理方式和二叉排序树的删除相同，删除后需要再次调整以满足特性。

B树（B-树）

  $B$树又称多路平衡查找树，$B$树中所有结点的孩子个数的最大值称为$B$树的阶，通常用$m$表示。当$B$树不为空时，满足如下特性：

  • 终端结点是最下面一层含有实际数据的结点，叶结点是查找失败的结点。

  • 树中每个结点至多有$m$棵子树，即至多含有$m-1$个关键字。

  • 若根结点不是终端结点，则至少有两棵子树。

  • 除根结点外的所有非叶节点至少有$\lceil \frac{m}{2} \rceil$棵子树，即至少含有$\lceil \frac{m}{2} \rceil-1$个关键字。

  • 非叶结点的结构如下：

    $Ki$是结点的关键字，满足$K_1指针$P{i-1}$所指子树中所有结点的关键字均小于$K_i$，$P_i$所指子树中所有结点的关键字均大于$K_i$</font>。$n$为结点中关键字个数。

  • 所有的叶节点出现在同一层次上，并且不带信息。

  • 含有$n$个关键字的$m$叉$B$树，其高度为：$logm(n+1) \le h \le log{\lceil \frac{m}{2} \rceil}{\frac{n+1}{2}}+1$

插入操作

  在插入新的关键字后，如果原结点关键字数量超出上限，则需要从

$\lceil \frac{m}{2} \rceil$处将关键字分为两部分，左部分包含的关键字在原结点，右部分包含的关键字在新结点，$\lceil \frac{m}{2} \rceil$处的关键字插入原结点的父结点。如果此时导致父结点关键字个数也超过上限，继续分裂直至结束。

  在插入新元素时，一定是插入到底层终端结点，使用查找及其相关操作来确定插入位置。

删除操作

  若被删除关键字在终端结点，则直接删除，需要注意关键字个数是否小于下限；若被删除关键字在非终端节点，则使用直接前驱或直接后继替代。

B+树

  • 与$B$树不同，$B+$树结点的子树个数与关键字个数相等。
  • 所有的叶子结点包含全部关键字以及指向对应记录的指针，叶结点中关键字按大小顺序排列，相邻叶结点按大小顺序相互链接。
  • 所有分支结点只包含各个子结点中关键字的最大值以及指针。
  • 其余性质与$B$树相同。

散列表

基本概念

  • 散列表（哈希表，$Hash{\ }Table$）：可以根据数据元素的关键字计算出它在散列表中的存储地址。
  • 散列函数（哈希表，$Hash{\ }Table$）：$Addr=H(Key)$建立了关键字和存储地址之间的映射关系。
  • 理想情况下查找元素的时间复杂度为$O(1)$。

散列函数的设计

  • 定义域必须涵盖所有可能出现的关键字。
  • 值域不能超出散列表的地址范围。
  • 尽可能减少冲突。
  • 散列函数尽量简单，能够快速计算出任意一个关键字对应的地址。

  除留余数法：$H(key)=key\%p$，$p$为最接近但不大于散列表长度的质数。对质数取余可以分布更均匀，减少冲突。

  直接定址法：$H(key)=key$或$H(key)=a*key+b$，这种方法计算简单且不会产生冲突，但是关键字分布不连续时，会产生较多的空间浪费。

  数字分析法：选取数码分布较为均匀的若干位作为散列地址，适用于关键字某几个数码分布均匀的场景。

  平方取中法：取关键字的平方值的中间几位作为散列地址，适用于关键字每位取值都不够均匀的场景，具体取的位数需要视情况而定。

冲突

  在散列表中插入一个数据元素时，需要根据关键字的值确定存储地址，如果改地址已经存储其他元素，则这种情况称为冲突或碰撞。不同关键字通过散列函数映射到同一存储地址，则被称为同义词。

拉链法

  使用链表将所有的同义词链接起来。

  • 插入操作：先计算散列地址，然后使用头插法或尾插法将元素插入散列地址对应的链表。
  • 查找操作：先计算散列地址，然后顺序查找链表。
  • 删除操作：先计算散列地址，然后查找链表并删除元素。

开放定址法

  先计算初始散列地址，如果发生冲突，就给新元素找另一个空闲位置。$H_i=(H(key)+d_i)\%m$，其中$d_i$为偏移量。构造探测序列来获取偏移量的方法主要有下面几种：

  • 线性探测法：$d_i=0,1,2,3,…,m-1$

  • 平方探测法：$d_i=0^2,1^2,-1^2,2^2,-2^2,…,k^2,-k^2$，其中$k \le \frac{m}{2}$

  • 双散列法：$hash_1=key\%m$，如果发生冲突，则计算$hash_2(key)=m-(key\%m),d_i=i \times hash_2(key)$，然后计算$H=(hash_1 + d_i)$解决冲突。

  • 伪随机序列法：$d_i$是伪随机序列，$H(key)=key\%m$，发生冲突时计算$H_i=(H(key)+d_i)\%m$，直至没有冲突。

  删除元素时需要进行逻辑删除而非物理删除，否则会引发错误。

  • 聚集（堆积）现象：处理冲突时，几个初始散列地址不同的元素争夺同一个后续散列地址的现象。线性探测法的特点就会导致聚集现象的发生，平方探测法可以减少聚集现象。
