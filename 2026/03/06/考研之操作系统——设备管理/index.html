设备管理

I/O设备基础知识

I/O设备基本概念

  ”$I/O$”指的是“输入/输出”。$I/O$设备就是可以将数据输入到计算机，或者可以接收计算机输出数据的外部设备。

  $I/O$设备按使用特性分类如下：

  • 人机交互类外部设备——数据传输速度慢，例如鼠标、键盘。
  • 存储设备——数据传输速度快，例如移动硬盘。
  • 网络通信设备——数据传输速度介于二者之间，例如调制解调器。

  按传输速率分类如下：

  • 低速设备——传输速率为每秒几到几百字节，例如鼠标、键盘。
  • 中速设备——传输速率为每秒千至上万字节，例如激光打印机。
  • 高速设备——传输速率为每秒数千到千兆字节，例如磁盘。

  按信息交换单位分类如下：

  • 块设备——传输速率较高，可寻址，例如磁盘。
  • 字符设备——传输速率较慢，不可寻址，例如鼠标、键盘。

I/O控制器

  $I/O$设备包括机械部件和电子部件。$CPU$无法直接控制$I/O$设备的机械部件，因此需要电子部件作为中介，实现$CPU$对设备的控制。

  • 机械部件：主要用来执行具体$I/O$操作。
  • 电子部件：通常是一块插入主板扩充槽的印刷电路板，这就是$I/O$控制器。

  $I/O$控制器有如下功能：

  • 接受和识别$CPU$发出的命令，用控制寄存器存储命令和参数。
  • 向$CPU$报告设备状态，用状态寄存器记录。
  • 数据交换，用数据寄存器暂存数据。
  • 地址识别，通过$CPU$提供的地址来判断要读写的寄存器。

  $I/O$控制器的组成如下：

  • $CPU$与控制器的接口：用于实现$CPU$与控制器之间的通信。$CPU$通过控制线发出命令，通过地址线指明要操作的设备；通过数据线来取出或放入数据。
  • $I/O$逻辑：负责接收和识别$CPU$发出的命令，再对设备发出命令。
  • 控制器与设备的接口：用于实现控制器与设备之间的通信。

  • 一个$I/O$控制器可能会对应多个设备。
  • 数据寄存器、控制寄存器、状态寄存器可能有多个，并且需要地址才能让$CPU$操作。可采用内存映像$I/O$或寄存器独立编址。
    • 内存映像$I/O$：控制器中的寄存器与内存统一编址，可以用内存的指令进行操作。
    • 寄存器独立编址：需要设置专门的指令操作控制器。

I/O控制方式

程序直接控制方式（轮询）

  1. $CPU$向控制器发出读指令，设备启动，状态寄存器设为$1$。
  2. 在设备没有准备好数据之前，$CPU$轮询检查控制器状态。
  3. 输入设备准备好数据后将数据传给控制器，并报告自身状态。
  4. 控制器将输入的数据放到数据寄存器中，并将状态改为$0$。
  5. $CPU$发现设备已就绪，将数据寄存器中的内容读入自身寄存器中，再放入内存。

  • 优点：实现简单。
  • 缺点：$CPU$干预的频率很频繁，需要不断轮询。

中断驱动方式

  1. 引入中断机制，$CPU$向控制器发出命令后，等待$I/O$的进程阻塞，切换至别的进程。
  2. 当$I/O$完成后，控制器发出中断信号，$CPU$会保存当前进程的运行环境信息，转去执行中断处理程序处理该中断。
  3. 处理中断时，$CPU$从$I/O$控制器读一个字的数据传送到自身寄存器，再写入内存。
  4. $CPU$恢复等待$I/O$的进程（或其他进程）的运行环境，然后继续执行。

  • 优点：$CPU$与$I/O$设备并行工作，利用率大大提升。
  • 缺点：频繁的中断处理会消耗较多时间。

直接存储器存取（DMA）

  1. $CPU$指明此次要进行的操作，并说明读入的数据量，存放位置及数据在外存的地址。
  2. $DMA$控制器根据要求完成数据的读/写工作，之后向$CPU$发出中断信号。该方式数据传送的单位是块，前两种方式的单位都是字。

  $DMA$控制器组成如下：

  • $DR$——数据寄存器，暂存从设备到内存或从内存到设备的数据。
  • $MAR$——内存地址寄存器，输入和输出数据的存放位置。
  • $DC$——数据计数器，剩余要读/写的字节数。
  • $CR$——命令/状态寄存器，存放命令和设备状态信息。

  • 优点：$CPU$介入频率进一步降低，数据传输效率进一步增加。
  • 缺点：$CPU$每发出一条$I/O$指令，只能读/写一个或多个连续的数据块，离散块需要多个指令。

通道控制方式

  通道：一种硬件，可以识别并执行一系列通道指令，可以看做简单的$CPU$。

  1. $CPU$向通道发出$I/O$指令，指明通道程序在内存中的位置，并指明要操作的$I/O$设备。之后$CPU$ 就切换到其他进程执行。
  2. 通道执行内存中的通道程序。
  3. 通道执行完规定的任务后，向$CPU$发出中断信号，之后$CPU$对中断进行处理。

  • 优点：$CPU$、通道、$I/O$设备并行工作，资源利用率高。
  • 缺点：实现复杂，需要硬件支持。

I/O软件层次结构

  $I/O$软件层次结构如下所示：

  • 用户层软件：与用户交互的接口，例如$I/O$操作相关的库函数。
  • 设备独立性软件：与设备硬件特性无关的功能。
    • 向上提供统一接口，例如系统调用。
    • 设备保护。
    • 差错处理。
    • 设备的分配和回收。
    • 数据缓冲区处理。
    • 使用逻辑设备表$(LUT)$，建立逻辑设备名到物理设备名的映射关系。
      • 整个系统只有一张$LUT$，所有用户不能使用相同的逻辑设备名。
      • 每个用户一张$LUT$，适合多用户操作系统。
  • 设备驱动程序：对硬件设备的具体控制。
  • 中断处理程序：$I/O$任务完成后，控制器通过发送中断信号告知$CPU$，$CPU$根据中断类型进行处理。

I/O应用程序接口

  • 字符设备接口：$get/put$系统调用向字符设备读/写一个字符。
  • 块设备接口：$read/write$系统调用向块设备的读写指针位置读/写多个字符，$seek$系统调用修改读写指针位置。
  • 网络设备接口：$socket$系统调用创建网络套接字，指明网络协议。

  • 阻塞$I/O$：应用程序发出$I/O$系统调用，进程需转为阻塞态等待。
  • 非阻塞$I/O$：应用程序发出$I/O$系统调用，系统调用可以迅速返回，进程无需转为阻塞态等待。

I/O核心子系统功能

假脱机技术(SPOOLing技术)

  脱机输入/输出技术是脱离主机的控制进行的输入/输出操作。假脱机技术是用软件的方式模拟脱机技术，在用户软件层实现。

  • 输入井：模拟脱机输入时的磁带，收容输入的数据。
  • 输出井：模拟脱机输出时的磁带，收容输出的数据。
  • 输入进程：模拟脱机输入时的外围控制机。
  • 输出进程：模拟脱机输出时的外围控制机。

  共享打印机：使用$SPOOLing$技术实现。当多个用户进程提出输出打印的请求时，系统会答应它们的请求，但是并不是真正把打印机分配给他们，而是由假脱机管理进程为每个进程做两件事：

  1. 在磁盘输出井为进程申请一个空闲缓冲区，并放入要打印的数据。
  2. 为用户进程申请一张空白的打印请求表，并将用户的打印请求填入表中，再将该表挂到假脱机文件队列上。

  当打印机空闲时，输出进程会从文件队列的队头取出一张打印请求表，并根据表中的要求进行打印。

设备的分配与回收

设备分配

  设备分配时应考虑的因素：

  • 设备固有属性：独占设备、共享设备、虚拟设备。
  • 设备分配算法：同进程调度算法。
  • 设备分配的安全性
    • 安全分配方式：为进程分配设备后将进程阻塞，直到$I/O$完成后才将其唤醒。
    • 不安全分配方式：为进程分配设备后进程可以继续执行，之后还可以发出新的$I/O$请求。

  设备分配方式有静态分配和动态分配。

设备分配管理中的数据结构

  • 设备控制表$(DCT)$：系统为每个设备配置一张$DCT$，用于记录设备情况。
    • 设备类型
    • 设备标识符——物理设备名
    • 设备状态
    • 指向控制器表的指针——每个设备由一个控制器控制，该指针能找到控制器的信息
    • 重复执行次数或时间——重复执行多次仍然不成功，则认为此次$I/O$失败
    • 设备队列的队首指针——指向正在等待该设备的进程队列
  • 控制器控制表$(COCT)$：每个设备控制器都会对应一张$COCT$，操作系统根据$COCT$的信息对控制器进行操作和管理。
    • 控制器标识符——各个控制器的唯一$ID$
    • 控制器状态
    • 指向通道表的指针——每个控制器由一个通道控制，该指针能找到相应通道的信息
    • 控制器队列的队首指针、队尾指针——指向正在等待该控制器的进程队列
  • 通道控制表$(CHCT)$：每个通道都会对应一张$CHCT$。操作系统根据$CHCT$的信息对通道进行操作和管理。
    • 通道标识符——各个通道的唯一$ID$
    • 通道状态
    • 与通道链接的控制器表首址——可通过该指针找到该通道管理的所有控制器相关信息
    • 通道队列的队首指针、队尾指针——指向正在等待该通道的进程队列
  • 系统设备表$(SDT)$：记录了系统中全部设备的情况，每个设备对应一个表目。每个表目记录设备的设备类型、设备标识符、$DCT$、驱动程序入口。

  设备分配步骤如下：

  1. 根据进程请求的物理设备名查找$SDT$。
  2. 根据$SDT$ 找到$DCT$，若设备忙碌则将进程$PCB$挂到设备等待队列，不忙碌则将设备分配给进程。
  3. 根据$DCT$找到$COCT$，若控制器忙碌则将进程$PCB$挂到控制器等待队列，不忙碌则将控制器分配给进程。
  4. 根据$COCT$找到$CHCT$，若通道忙碌则将进程$PCB$挂到通道等待队列，不忙碌则将通道分配给进程。
  5. 设备、控制器和通道都分配成功时，这次设备分配才算完成。

  该方法的缺点如下：

  • 用户编程时必须使用物理设备名，但底层细节对用户不透明，不方便编程。
  • 若换了一个物理设备，则程序无法运行。
  • 若进程请求的物理设备正在忙碌，则即使系统中还有同类型的设备，进程也必须阻塞等待。

  改进方法：采用逻辑设备表，用户使用时提供逻辑设备名即可。

缓冲区管理

  硬件作为缓冲区的成本较高，容量较小，一般使用内存作为缓冲区。

  缓冲区作用如下：

  1. 缓和$CPU$与$I/O$设备之间速度不匹配的矛盾。
  2. 减少$CPU$的中断频率，放宽对$CPU$中断响应时间的限制。
  3. 解决数据粒度不匹配的问题。
  4. 提高$CPU$与$I/O$设备之间的并行性。

单缓冲

  操作系统在内存中为进程分配一个缓冲区，大小一般为一个块。缓冲区数据非空，不能往缓冲区放入数据，只能把数据取出；缓冲区为空，可以往缓冲区放入数据，但必须充满以后，才能把数据取出。

  初始状态是工作区满，缓冲区空。设$T$为数据从设备到缓冲区的时间，$C$为$CPU$处理时间，$M$为数据从缓冲区到工作区的时间，则处理一块数据平均耗时：$Max(T,C)+M$

双缓冲

  操作系统在内存中为进程分配两个缓冲区。

  初始状态是工作区空，一个缓冲区满，另一个缓冲区空。设$T$为数据从设备到缓冲区的时间，$C$为$CPU$处理时间，$M$为数据从缓冲区到工作区的时间，则处理一块数据平均耗时：$Max(T,C+M)$

循环缓冲区

  将多个大小相等的缓冲区链接成一个循环队列，队列中有$in$和$out$两个指针。

  • $in$指针：指向下一个可以放入数据的空缓冲区。
  • $out$指针：指向下一个可以取出数据的满缓冲区。

缓冲池

  由系统中共用的缓冲区组成，可以分为空缓存队列、输入队列（装满输入数据）和输出队列（装满输出数据）。根据功能，有如下四种工作缓冲区：

磁盘

磁盘的结构

  • 磁盘的表面由一些磁性物质组成，用来记录二进制数据。
  • 磁盘的盘面被划分为一圈圈磁道。
  • 一个磁道被划分为一个个扇区，每个扇区就是一个磁盘块，各个扇区存放的数据量相同。最内侧磁道上扇区面积最小，因此数据密度最大。
  • 磁盘是由多个盘片垒起来的，每个盘片对应一个磁头。一个盘片可能会有正反两个盘面。
  • 所有磁头连在同一个磁臂上。
  • 所有盘面中相对位置相同的磁道组成柱面。
  • 可用（柱面号，盘面号，扇区号）定位任意一个磁盘块。
  • 根据磁头是否可移动分为活动头磁盘和固定头磁盘。下图中左边是活动头磁盘，右边是固定头磁盘。

  • 根据盘片是否可更换分为固定盘磁盘和可换盘磁盘。

磁盘调度算法

  • 寻道时间$T_S$：读/写数据前，将磁头移动到指定磁道花费的时间。
    • 启动磁头臂花费时间为$s$。
    • 移动磁头跨越$n$条磁道花费时间为$m{\times}n$。
    • $T_S=s+m{\times}n$
  • 延迟时间$T_R$：旋转磁盘让磁头定位到目标扇区需要的时间。若转速为$r$，则平均延迟时间为$T_R={\frac{1}{2}}*{\frac{1}{r}}={\frac{1}{2r}}$。
  • 传输时间$T_t$：从磁盘读出或向磁盘写入数据经历的时间。若转速为$r$，读/写字节数为$b$，每个磁道上的字节数为$N$，则$T_t={\frac{1}{r}}*{\frac{b}{N}}={\frac{b}{rN}}$
  • 总时间$T_a=T_S+T_R+T_t$

先来先服务算法(FCFS)

  根据进程请求访问磁盘的先后顺序进行调度。

  • 优点：公平，请求访问磁道比较集中则性能还可以。
  • 缺点：请求访问的磁道分散时，性能很差。

最短寻找时间(SSTF)

  优先处理离当前磁头最近的磁道。

  • 优点：性能较好，平均寻道时间短。
  • 缺点：可能产生饥饿现象。

扫描算法(SCAN)

  只有磁头移动到最外侧磁道时才往内移动，移动到最内侧磁道时才往外移动。

  • 优点：性能较好，平均寻道时间短，不会产生饥饿现象。
  • 缺点：只有到达最边上的磁道时才能改变磁头移动方向，并且对于各个位置磁道的响应频率不平均。

LOOK调度算法

  在扫描算法基础上，如果磁头移动方向上已经没有别的请求，就可以立即改变磁头移动方向。

  • 优点：相比$SCAN$算法寻道时间进一步缩短。

循环扫描算法(C-SCAN)

  只有磁头朝某个特定方向移动时才处理磁道访问请求，而返回时直接快速移动至起始端而不处理任何请求。

  • 优点：与$SCAN$相比，各位置磁道响应频率很平均。
  • 缺点：与$SCAN$相比，平均寻道时间更长。

C-LOOK调度算法

  在$C-SCAN$算法基础上，如果磁头移动的方向上已经没有磁道访问请求了，就可以立即让磁头返回，并且磁头只需要返回到有磁道访问请求的位置即可。

  • 优点：相比$C-SCAN$算法寻道时间进一步缩短。

减少磁盘延迟时间

  磁头读入一个扇区数据后需要一小段时间处理，如果逻辑上相邻的扇区在物理上也相邻，则读入几个连续的逻辑扇区可能需要转好几圈，导致延迟时间增加。

  • 交替编号：让逻辑上相邻的扇区在物理上有一定的间隔，使读取连续的逻辑扇区所需要的延迟时间更小。
  • 错位命名：让相邻盘面的扇区编号“错位”，与交替编号原理相似。

磁盘的管理

  • 磁盘初始化：先进行低级格式化，将磁道划分为扇区，然后进行逻辑格式化。扇区可分为头、数据区域、尾三部分。头尾部分存储管理扇区的各种数据结构，包括扇区校验码、循环冗余校验码等。

  • 引导块：计算机开机时需要进行一系列初始化的工作，通过执行初始化程序（自举程序）完成。由于$ROM$中存放的数据不可改变，因此只有自举装入程序在$ROM$中，完整的自举程序在引导块中。

    开机时计算机先运行“自举装入程序”，通过执行该程序可找到引导块，并将完整的自举程序读入内存，完成初始化。

  • 坏块的管理：对于简单的磁盘，可以在逻辑格式化时对整个磁盘进行坏块检查，标明坏扇区。对于复杂的磁盘，磁盘控制器会维护一个坏块链表。在磁盘出厂前进行低级格式化时就将坏块链初始化，同时会保留一些“备用扇区”，用于替换坏块。

固态硬盘SSD

  • 原理：基于闪存技术，属于电可擦除$ROM$，即$EEPROM$。
  • 组成：由闪存翻译层和存储介质组成。闪存翻译层负责翻译逻辑块号，找到对应页；存储介质包含多个闪存芯片，每个芯片包含多个块，每个块包含多个页。
  • 读写性能特性
    • 以页为单位读/写——相当于扇区。
    • 以块为单位擦除。擦干净的块中每页都可以写一次，读无限次。
    • 支持随机访问，系统给定一个逻辑地址，闪存翻译层可通过电路迅速定位到对应的物理地址。
    • 读快、写慢。要写的页如果有数据，则不能写入，需要将块内其他页全部复制到一个新的块中，再写入新的页。
  • 与机械硬盘相比的特点
    • $SSD$读写速度快，随机访问性能高，用电路控制访问位置；机械硬盘通过移动磁臂旋转磁盘控制访问位置，有寻道时间和旋转延迟。
    • $SSD$安静无噪音、耐摔抗震、能耗低、更贵。
    • $SSD$的一个块被擦除次数过多可能会坏掉，机械硬盘的扇区不会因为写的次数太多而坏掉。
  • 磨损均衡技术：将擦除平均分布在各个块上，以提升使用寿命
    • 动态磨损均衡：写入数据时，优先选择累计擦除次数少的新闪存块。
    • 静态磨损均衡：$SSD$监测并自动进行数据分配、迁移，老旧闪存块承担以读为主的储存任务，较新闪存块承担更多的写任务。
