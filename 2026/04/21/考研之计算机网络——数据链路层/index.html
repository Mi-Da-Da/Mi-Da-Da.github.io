数据链路层

基础知识

基本概念

  • 数据链路层使用物理层提供的“比特传输”服务。

  • 数据链路层为网络层提供服务，将网络层的IP数据报（分组）封装成帧，传输给下一个相邻结点。

  • 物理链路：传输介质和物理层实现了相邻结点之间的物理链路。

  • 逻辑链路：数据链路层需要基于“物理链路”，实现相邻结点之间逻辑上无差错的“数据链路”。

功能

  • 封装成帧（组帧）
    • 帧定界：如何让接收方能够确定帧的界限。
    • 透明传输：接收方链路层要能从收到的帧内恢复原始$SDU$，对上层屏蔽。
  • 差错控制：发现并解决一个帧内部的“位错”。
    • 解决方案一：接收方发现比特错后丢弃帧，发送方重传帧。
    • 解决方案二：由接收方发现并纠正比特错误，采用纠错编码技术。
  • 可靠传输：发现并解决“帧错误”。
    • 帧丢失：发送$1234$，收到$124$。
    • 帧重复：发送$1234$，收到$12334$。
    • 帧失序：发送$1234$，收到$1324$。
  • 流量控制：控制发送方发送帧的速率，让接收方能够及时接收。
  • 介质访问控制：广播信道需要实现此功能，点对点信道不需要实现。

组帧

  帧由首部、数据部分、尾部构成，首部和尾部主要是控制信息。

字符计数法

  在每个帧的开头，用一个定长计数字段表示帧长，帧长包括计数字段长度和帧的数据部分长度。

  • 缺点：任何一个计数字段出错，都会导致后续所有帧无法定界。

字节填充法

  使用$ASCII$字符控制，开头使用$SOH(0x01)$，结尾使用$EOT(0x04)$，转义字符使用$ESC(0X1B)$。

零比特填充法

  使用特殊的比特串$0x7E(01111110)$标记帧开始和结尾。

  • 发送方对数据部分进行处理，在遇到连续的$5$个$1$时，填充一个$0$。
  • 接收方对数据部分进行处理，在遇到连续的$5$个$1$时，删除一个$0$。

  • 该方法使用硬件可以高效实现，目前有$HDLC$协议和$PPP$协议。

违规编码法

  使用违规编码（基于曼彻斯特编码），用违规信号表示帧的开头和结尾，该方法需要物理层的配合。

差错控制

奇偶校验码

  • 奇校验码：整个校验码（有效位和校验码）中$1$的个数为奇数。
  • 偶校验码：整个校验码（有效位和校验码）中$1$的个数为偶数。
    • 发送方：所有位进行异或运算，得到的结果即为偶校验码。
    • 接收方：所有位进行异或运算，与校验位进行比对，不一致则出现错误。

  • 缺点：奇偶校验码仅能检测出奇数位错误，无纠错能力。

循环冗余校验码(CRC)

  数据发送和接收方约定一个“除数”，$K$个信息位和$R$个校验位构成“被除数”，添加校验位后需要保证除法的余数为$0$，收到数据后使用除法检查结果是否为$0$即可。

  • 一般使用生成多项式的方式给出除数，例如$G(x)=x^3+x^2+1$，该多项式可以看做$1 \cdot x^3 + 1 \cdot x^2 + 0 \cdot x + 1 \cdot x^0$，因此对应的除数就是$1101$。
  • $K$对应信息码的长度，$R$对应生成多项式的最高次幂。

  构造校验码的步骤如下：

  1. 确定$K$和$R$。
  2. 确定生成多项式对应的二进制码。
  3. 原始信息码左移$R$位。
  4. 移位后的信息码和生成多项式对应的二进制码进行模$2$除法（模$2$加减法即为异或），产生$3$位余数，将其与移位后的信息码进行或运算即可（将余数拼到原始信息码的后面）。

  对于确定的生成多项式，出错位与余数是相对应的。如下的例子中，生成多项式为$1101$，信息码为$0100$。

  • 可检测出所有奇数个错误。
  • 可检测出所有双比特的错误。
  • 可检测出所有小于等于校验位长度的连续错误。
  • $K$个信息位，$R$个检验位，若生成多项式选择得当，且$2^R \ge K+R+1$，则$CRC$码可纠正$1$位错。

汉明（海明）校验码

  将信息位分组进行偶校验，每个分组对应一个校验位，多个校验位标注出错位置。计算步骤如下：

  1. 确定汉明码的位数：$2^k \ge n+k+1$，$n$为信息位长度，$k$为校验位长度。设信息位$D_4D_3D_2D_1$，校验位$P_3P_2P_1$，对应的汉明码为$H_7H_6H_5H_4H_3H_2H_1$。
  2. 确定校验位的分布：校验位$P_i$放到汉明码位号为$2^{i-1}$的位置。

  1. 求校验位的值：将信息位的位置序号用$k$位二进制数表示出来，检验位$P_i$与位置序号二进制数第$i$位为$1$的信息位归为同一分组，计算偶校验位并填入对应的汉明码位置。

  1. 纠错：对各个分组计算偶校验位$S_i$，并添加全体偶校验位。
    • $S_i$全为$0$并且全体偶校验成功，说明没有出现错误。
    • $Si$不全为$0$并且全体偶校验失败，说明有$1$位出现错误，该位号的二进制表示为$S_kS{k-1}…S_1$，纠正即可。
    • $S_i$不全为$0$并且全体偶校验成功，说明有$2$位错误，需要重传。
    • 汉明码的检错能力只有$2$位，如果大于$2$位应当另行讨论。

  注意：二进制位的编号可能是从小到大也可能是从大到小，应当根据编号顺序进行调整。

流量控制与可靠传输

相关机制

滑动窗口机制

  • 发送窗口$W_T$：发送方当前允许发送的帧。
  • 接收窗口$W_R$：接收方当前允许接收的帧。

  • 接收方会接收当前接收窗口内的帧，接收窗口外的帧会被丢弃。接收完后接收窗口会向右滑动，同时接收方会控制发送方的发送窗口向右滑动。

确认机制

  • 确认帧$ACK_i$：接收方收到$i$号帧并且检验无差错，则给发送方返回确认帧$ACK_i$。
  • 否认帧$NAK_i$：接收方收到$i$号帧并且检验有差错，则给发送方返回否认帧$NAK_i$。

重传机制

  • 超时重传：若发送方超时未接收到确认帧，则重传$i$号帧。
  • 请求重传：若发送方收到否认帧，则重传$i$号帧。

帧编号

  为了支持以上机制正确运行，至少用$nbit$给帧编号，要求$W_T+W_R \le 2^n$，否则会导致帧序号混乱，数据帧被错误接收。

停止等待协议(S-W)

  • 滑动窗口机制：发送方和接收方窗口大小均为$1$，不存在帧失序的问题。
  • 确认机制：使用确认帧机制。
  • 重传机制：使用超时重传机制。
  • 帧编号：仅需$1bit$给帧编号。

实现流量控制

  1. 发送方发送数据帧并开启计时器，如果计时器超时则自动重传。
  2. 接收方收到数据帧确认无误，窗口向后滑动并给发送方发送确认帧。
  3. 发送窗口收到确认帧，发送窗口向后滑动。
  4. 接收方控制了发送窗口的滑动速度，实现了流量控制。

实现可靠传输

  • 帧丢失：发送方发送数据帧并开启计时器，计时器超时仍未接收到确认帧，则自动重传并重置计时器。
  • 帧重复：
    1. 接收方发送确认帧并向右滑动接收窗口，但是确认帧丢失。
    2. 发送方超时重传数据帧。
    3. 接收方丢弃重复帧，并返回重复帧的确认帧。
    4. 发送方收到确认帧，向右滑动发送窗口。
  • 帧错误：
    1. 接收方收到数据帧发现校验出错，直接丢弃。
    2. 发送方超时重传数据帧。
    3. 接收方收到重传的数据帧检验无误，向右滑动接收窗口，返回确认帧。
    4. 发送方收到确认帧，向右滑动发送窗口。

后退N帧协议(GBN)

  • 滑动窗口机制：发送窗口$W_T > 1$，接收窗口$W_R=1$。
  • 确认机制：使用累积确认，连续收到多个数据帧，仅返回最后一个帧的确认帧。
  • 重传机制：使用超时重传机制。
  • 帧编号：使用$nbit$给帧编号，$W_T+W_R \le 2^n$。
  • 缺点：如果接收方接收帧的速度很慢，或者在信道误码率非常高的情况下，会导致发送方多次后退，传输效率低。

实现可靠传输

  • 帧丢失：
    1. 某个数据帧因通信故障丢失，后续帧落在接收窗口之外被接收方丢弃。
    2. 接收方返回最后一个正确接收的数据帧的确认帧。
    3. 发送方收到$ACK_i$，回退到$i+1$号帧并重新发送。
  • 帧重复：
    1. 接收方发送确认帧并向右滑动接收窗口，但是确认帧丢失。
    2. 发送方超时重传数据帧。
    3. 接收方丢弃重复帧，并返回最后一个正确接收的数据帧的确认帧。
    4. 发送方收到确认帧，向右滑动发送窗口。

选择重传协议(SR)

  • 滑动窗口机制：发送窗口$W_T > 1$，接收窗口$W_R>1$。
  • 确认机制：不支持累积确认，必须逐帧确认，如果出现差错则返回否认帧$NAK_i$。
  • 重传机制：使用超时重传机制。
  • 帧编号：使用$nbit$给帧编号，$W_T+W_R \le 2^n$，并且$W_R \le W_T$。

实现可靠传输

  • 帧丢失：

    1. 发送方发送$4567$，接收方收到$467$并返回确认帧，向右滑动接收窗口到$5$号帧的位置，同时发送窗口也向右滑动。

    1. 发送方未接收到$5$号帧的确认帧，超时重传。

  • 帧重复：

    1. 发送方发送$1234$，接收方收到$1234$并返回确认帧，$1$号和$3$号的确认帧丢失。
    2. 发送方向右滑动发送窗口，超时重传未收到确认帧的数据帧。
    3. 接收方丢弃重复帧，并返回重复帧的确认帧。
    4. 发送方收到确认帧，向右滑动发送窗口。

  • 帧出错：

    1. 发送方发送$4567$，接收方收到$4567$，但是$5$号帧出错，返回$467$号的确认帧和$5$号的否认帧。
    2. 发送方主动重传$5$号帧并重置计时器，提升传输效率。

介质访问控制

信道划分

时分复用(TDM)

  将时间分为等长的“$TDM$帧”，每个“$TDM$帧”又分为等长的$m$个“时隙”，将$m$个“时隙”分配给$m$对用户（节点）使用。该技术有如下的缺点：

  • 每个节点最多只能分配到信道总带宽的$\frac{1}{m}$。
  • 某个节点暂时不发送数据，会导致被分配的时隙闲置，使得信道利用率降低。

统计时分复用(STDM)

  在时分复用的基础上，动态按序分配时隙，某个时隙的用户不需要传输数据，则分配给其他需要传输数据的用户，

频分复用(FDM)

  将信道的总频带划分为多个子频带，每个子频带作为一个子信道，每对用户使用一个子信道进行通信。

  • 复用器：将各节点发出的信号“复合”后传输到共享信道上。
  • 分用器：将各个子频带信号“分离”出来。

  该技术能够让多个节点同时发送信号，充分利用信道带宽；但是只能用于模拟信号的传输。

波分复用(WDM)

  将光信号进行频分复用，使用不同波长的光信号作为子信道。

码分复用(CDM)

  1. 给各节点分配专属“码片序列”。码片序列包含$m$个码片（信号值），可看做$m$维向量（分量通常取$-1$或$1$）。

    • 要求各节点的$m$维向量必须相互正交，这样在收到不同节点的叠加信号时可以进行分离。

  2. 节点发送$m$个信号值与码片序列相同，表示比特$1$；相反则为比特$0$。

  3. 当多个发送方同时发送数据时，信号在传输过程中叠加，本质为多个$m$维向量的加法。
  4. 接收方收到的是叠加信号，需要从中分离出各发送方的数据。叠加信号与发送方码片序列计算“规格化内积”，得出对应发送方发送的信号。

随机访问

ALOHA协议

  • 纯$ALOHA$协议：类似停止等待协议。

  • 时隙$ALOHA$协议：避免了用户发送数据的随意性，降低了冲突概率，提高了信道利用率。

载波监听多路访问协议(CSMA)

  在$ALOHA$协议的基础上进行改进，发送数据之前先监听信道是否空闲，只有信道空闲时才会尝试发送。

  • $1-$坚持$CSMA$协议：信道利用率高；多个节点都准备好数据并且信道空闲时，会同时发送数据，导致冲突概率变大。

  • 非坚持$CSMA$协议：随机推迟一段时间再尝试监听，降低冲突概率；信道刚恢复空闲时，可能不会立即被使用。

CSMA/CD协议（冲突检测）

  先听后发，边听边发，冲突停发，随机重发。

  • 争用期：最大单向传播时延（距离最远的两个节点）的两倍。如果争用期内没检测到冲突，本次帧发送就不再可能发送冲突。
  • 最短帧长：$2 \times$最大单向传播时延$\times$信道带宽，若收到的帧小于最短帧长，则视为无效。
    • 小于最短帧长时，会导致节点误认为发送过程中没有发送冲突，但实际上已经发生了冲突。
    • 如果实际要发送的数据很少，可填充至合法长度后再发送。
  • 最长帧长：规定最长帧长防止某些节点一直占用信道。以太网规定最短帧长为$64B$，最长帧长为$1518B$。

CSMA/CA协议（冲突避免）

  适用于无线网络，例如$IEEE802.11$标准的无线局域网$(WiFi)$。

  • $AP$：接入点，也就是连接的无线$WiFi$热点。
  • 硬件上难以实现“边听边发，冲突检测”：接收信号的强度往往远小于发送信号的强度，且在无线介质上信号强度的动态变化范围很大。
  • 存在“隐蔽站”问题：在无线通信中，并非所有站点都能够听见对方，发送节点处没有冲突并不意味着接收节点处就没有冲突。

  • 帧间间隔$(IFS)$：

    • 分布式协调$IFS(DIFS)$：最长的帧间间隔。
    • 短$IFS(SIFS)$：最短的帧间间隔。预留$SIFS$用于处理收到的帧。

  • 发送方先听后发，忙则退避。

    • 若信道空闲，间隔$DIFS$后，再发送帧，一口气发完，发送过程中不检测冲突。
    • 若信道不空闲，则进行“随机退避”。
    • 随机退避：用二进制指数退避算法确定一段随机退避时间（倒计时），发送方持续监听空闲信道，当信道空闲时扣除倒计时，不空闲时暂停倒计时。倒计时结束则立即发送数据帧。
  • 接收方使用停止等待协议，每收到一个正确数据帧都返回$ACK$，若发送方超时未收到$ACK$，则进行“随机退避”。
  • 使用信道预约机制解决”隐藏站“问题，步骤如下：
    1. 发送方发送$RTS$控制帧.。
      • $RTS$控制帧（请求发送）：包括源地址、目的地址和这次通信所需的持续时间。
    2. $AP$广播$CTS$控制帧。
      • $CTS$控制帧（允许发送）：和$RTS$控制帧内容相同。
    3. 其他无关节点收到$CTS$控制帧后自觉“禁言”一段时间，发送方收到$CTS$控制帧后可以发送数据。
      • 如果超时未收到$CTS$控制帧，则说明预约失败，随机退避后再次预约。
    4. $AP$收到数据帧后，进行$CRC$校验，若无差错就返回$ACK$帧。

轮询访问

  主要采用令牌环网技术。该技术使用环形拓扑结构，各节点“轮询访问”信道，不会发生信道冲突，效率高，因此适用于负载高的网络。通过令牌传递协议实现介质访问控制。

  • 令牌帧：只有获得令牌的节点才能往信道上发送数据帧，传递一次数据帧就需要释放令牌。如果当前节点没有数据帧需要传递，则将令牌传递给下一个节点。

  • 数据帧：包含源地址、目的地址、令牌号等信息。目的节点收到后会复制数据，并将$FS$标记为$true$，说明已接收。数据帧回到源节点后，如果发现异常状况，就尝试重发；若无异常，就将令牌传递下一个节点。

  • 令牌环网的集中控制站$(MAU)$：用于集中控制令牌环网。

局域网

IEEE802

  • $IEEE$：电气电子工程师学会。
  • $IEEE802$委员会：致力于研究局域网和城域网的物理层和$MAC$层中定义的服务和协议，对应$OSI$网络参考模型的最低两层。层次划分为：
    • 物理层：某个具体局域网技术的研究范畴
    • 介质访问控制子层：研究与访问传输介质有关的部分功能（如：组帧、差错控制、透明传输、介质访问控制等）。
  • 常见的工作组：
    • $802.3$：以太网技术。
    • $802.5$：令牌环网技术，已被解散。
    • $802.11$：$WiFi$技术。
    • $802.1Q$：$VLAN$技术。
